# OpenBLAS release build evidence

Inspected official OpenMathLib/OpenBLAS release packages, not only CI source.

| Evidence | OpenBLAS 0.3.18 x64 | OpenBLAS 0.3.34 x64/x86 |
| --- | --- | --- |
| Compiler identification in DLL and LAPACK archive members | GCC 9.3.0 | GCC 9.3.0 |
| DLL PE linker version and DWARF assembler producer | GNU binutils 2.28 | GNU binutils 2.28 |
| Runtime debug paths | MXE, MinGW-w64 8.0.0 | MXE, MinGW-w64 8.0.0 |
| DLL imports | KERNEL32.dll, msvcrt.dll | KERNEL32.dll, msvcrt.dll |
| BLAS integer interface | LP64 (32-bit integers) | LP64 (32-bit integers) |
| Package configuration | generic, dynamic architecture, older CPUs, 64 threads, no affinity, no OpenMP | Same (GENERIC is uppercase) |
| GNU runtime linkage | Fortran, quadmath, winpthreads and libgcc definitions inside DLL | Same |
| Exception model | x64 SEH | x64 SEH / x86 SJLJ |

The x64 0.3.18 upstream DLL is byte-identical to the DLL distributed with the
existing PHP/Tensor build: SHA256
`89e9e366470fa5d996f4f8bd4933600700a0e2af8d19ce6a4d7bc9d955f57ab1`.

The 0.3.34 release DLL hashes are:

- x64: `0486735c359a67419d8832e3c40e2837f8762baebcdf4b62d3b18c91f9ece12e`
- x86: `b0ab9671a16a18f22a73f57ea71ce99133cff35bdefd528780df7ff84f1da4d5`

## Additional binary evidence

- Both versions' `blas_server.obj` use Windows events and critical sections for
  OpenBLAS workers. Statically linked winpthreads also exists in the GNU runtime;
  that is distinct from OpenBLAS's worker backend.
- Disassembly of `exec_blas_async` contains `fnstcw` and `stmxcsr`; its worker
  contains `ldmxcsr` and `fldcw`. This confirms `CONSISTENT_FPCSR=1` in both versions.
- `dgesdd.o` in the static archive identifies GCC 9.3.0: LAPACK was compiled from
  Fortran, not the C-converted fallback.
- The `.pc` files retain `win64` / `win32` installation prefixes and report
  `DYNAMIC_ARCH=1 DYNAMIC_OLDER=1 NO_AFFINITY=1 MAX_THREADS=64`, with CBLAS,
  LAPACK and LAPACKE enabled and ILP64/OpenMP disabled.
- The release CMake package files are also generated by `Makefile.install`;
  their presence does not demonstrate that CMake built the DLL.

The matching MXE source recipe in commit
`151f5502387653ea87fddf325b4e952972d7717d` has GCC 9.3.0 in `plugins/gcc9`,
MinGW-w64 8.0.0, binutils 2.28, POSIX compiler threading, x86 SJLJ and x64 SEH.
The exact MXE checkout and complete command line are not recoverable from the
inspected artifacts alone.

## Sources and reproducible inspection

- [Upstream release recipe](https://github.com/OpenMathLib/OpenBLAS/blob/v0.3.34/docs/install.md)
- [Maintainer's MXE/GCC description](https://github.com/OpenMathLib/OpenBLAS/issues/4274#issuecomment-1779916970)
- [MXE compiler recipe](https://github.com/mxe/mxe/blob/151f5502387653ea87fddf325b4e952972d7717d/src/gcc.mk)
- [Upstream CI (build/test, no release-upload step)](https://github.com/OpenMathLib/OpenBLAS/blob/v0.3.34/.github/workflows/dynamic_arch.yml)

Use `objdump -p` for imports and linker version, `objdump -t` for static runtime
definitions, `dwarfdump --debug-info` for compiler and source paths, and extract
`dgesdd.o` / `blas_server.obj` from `libopenblas.a` to inspect compilation and
floating-point state propagation. Check installed headers and `openblas.pc`
against the package's actual version.

The source-rebuild trial installs GCC 9.3.0 with the same exception/threading
models, but its WinLibs distribution has MinGW-w64 7.0.0 and binutils 2.34.
Therefore it must pass explicit compatibility tests; it is not a byte-identical
reproduction of the original MXE toolchain.

## Verified source-build results

- 0.3.18 / VS16:
  [x86](https://github.com/shivammathur/test-setup-php/actions/runs/35460086400) and
  [x64](https://github.com/shivammathur/test-setup-php/actions/runs/35461792229):
  all 9,259 exports and ordinals match the existing PHP package, with the same
  runtime DLL dependencies and configuration. Numerical tests and old/new
  consumer/DLL cross-tests pass. Native Tensor TS and NTS each report 379 tests,
  517 assertions, eight upstream skips and no failures.
- 0.3.34 / VS16:
  [x86](https://github.com/shivammathur/test-setup-php/actions/runs/35460612704) and
  [x64](https://github.com/shivammathur/test-setup-php/actions/runs/35461998923):
  all 9,548 exports and ordinals match the official 0.3.34 release. The same
  numerical and cross-tests pass, as do Tensor TS and NTS with the same counts.
- 0.3.34 / VS17:
  [x86](https://github.com/shivammathur/test-setup-php/actions/runs/35461058651) and
  [x64](https://github.com/shivammathur/test-setup-php/actions/runs/35461450371):
  the same export, runtime, numerical and Tensor checks pass.
- [0.3.34 x86 and x64 / VS18](https://github.com/shivammathur/test-setup-php/actions/runs/35462772663):
  the direct MSVC export, runtime and numerical checks pass on both architectures.
  The [earlier Tensor trial](https://github.com/shivammathur/test-setup-php/actions/runs/35461058514)
  showed that Tensor 3.0.11 fails
  to link PHP 8.6's `zval_dtor` and `_zval_get_string_func`, unrelated to OpenBLAS.
  PHP 8.6 Tensor compatibility changes are out of scope; subsequent VS18 runs
  retain the direct OpenBLAS checks and skip the Tensor job.
- Official 0.3.34 control packages also pass the MSVC numerical tests on
  [VS16](https://github.com/shivammathur/test-setup-php/actions/runs/35459676265),
  [VS17](https://github.com/shivammathur/test-setup-php/actions/runs/35459677660), and
  [VS18](https://github.com/shivammathur/test-setup-php/actions/runs/35459679356),
  for both architectures. These controls are not results for our rebuilt x64 DLLs.

The source-build tests above used the trial build commits recorded by their
workflow runs. Subsequent packaging changes in PR #50 add unique license
filenames, the MinGW runtime notices, and the PECL download URL in the SBOMs.
Local generation checks cover both the PECL URL override and unchanged PHP SDK
default, plus extraction of the complete MinGW license text. Publication still
requires fresh builds from the final upstream commit.

## Upgrading existing consumers

Existing Tensor DLLs import OpenBLAS by ordinal. Upstream changed ordinals between
0.3.18 and 0.3.34: for example, ordinal 6580 is `cblas_dgemm` in 0.3.18, but
`sgelqs` in 0.3.34. The tests compare ordinals within each release version, not
between different versions. Rebuild and package Tensor with the matching new
OpenBLAS library; do not replace only the DLL in an existing Tensor package.
